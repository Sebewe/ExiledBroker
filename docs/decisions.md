## Scope

| Date | Decision |
|---|---|
| 2026-10-21 | **PoE1 only for now** (a league launches in about a month). The `game` column stays on leagues and items so PoE2 can be added later. |
| 2026-10-21 | **League kinds:** *challenge* = the main 3–4 month leagues (Settlers, Mirage, …); *event* = short leagues of a few weeks (Ancestors, Phrecia), nested in another league's window, with far fewer players; *ruthless* = Ruthless variants. Only each challenge league's softcore files are kept; Standard, Hardcore and private leagues in the zips are skipped. |
| 2026-10-21 | **Event and Ruthless leagues are excluded** from data and analysis. Most players don't play them and their markets don't follow normal trends ([data.md](data.md#scope-whats-left-out)), so including them would make predictions worse. Every command defaults to challenge leagues, and the Ancestors data was deleted. `--kind` / `-l` can still select one. |
| 2026-10-21 | **Currency and uniques only** (plus divination cards). Base items, gems, cluster jewels, maps and other types are skipped. Currency-like types (scarabs, essences, fossils, oils, …) are keyed by name (`currency:<slug>`) like the currency file and the exchange, so one item has one id in every source. Uniques keep `ninja:<Id>`. |
| 2026-10-21 | **Only the core drop pool is shown** (`ingest/core_pool.py`). Currency, essences and scarabs are limited to poe.ninja's *current-league* lists (minus Catalysts), snapshotted in `reference_data`, checked daily and replaced only if the list changed, so items whose mechanic didn't go core drop out. This replaced an earlier running union. Cards are limited to what NeverSink's filter shows. Overrides go in `config/core_pool.toml` (`exclude` everywhere, `[include]` per group). Catalysts were left out at first; see 2026-10-22. |
| 2026-10-21 | **Built for a new league's data arriving.** At launch every price is null, and GGG publishes each hour only after it ends. A league can be registered before it has data (`--start`), and every view handles none / one hour / a few days. Day comparisons appear only once there are two days. Applies to every new view ([data.md](data.md#a-new-leagues-data)). |
| 2026-10-22 | **Catalysts, fragments and oils are currency.** They trade on the exchange like any currency, so the Currency group now takes poe.ninja's Currency list with Catalysts, plus its Fragment and Oil lists (183 names for Allflame instead of 88). Each list is its own snapshot (`core_pool/type/<Type>`); the old per-group snapshots are deleted on refresh. Hosted hourly rows grow ~22% (Allflame 260k → 319k); the daily pool check makes 5 list requests instead of 3. Daily dumps already had them (fragments and catalysts are in the currency file, oils in the items file). |
| 2026-10-25 | **Uniques are out of scope.** Their prices change dramatically between leagues with whichever builds are popular, and the few that don't are generally gambling uniques, so past leagues don't predict them and they matter less to the site. Dropped from the plan: the poe.ninja live poller (it existed only to record uniques' launch hours), unique card rewards in expected-value work, unidentified uniques as tracked items. The daily dumps keep loading them (cheap, already there, used by finding 1). Don't propose unique work again unless the user brings it up. |
| 2026-10-22 | **Hosting launches with live-league data only.** Past leagues are for building and testing and stay local; anyone after old prices has poe.ninja. Hosted data is the running league's launch fortnight plus recent hours, a few hundred MB at most. |

## Data and ingest

| Date | Decision |
|---|---|
| 2026-10-21 | **DuckDB + Parquet storage.** |
| 2026-10-21 | **Ingest is local and resumable.** Downloads continue with HTTP Range + If-Range; outputs are written to a temp path and renamed, so a finished file is its own completion marker (no state file to corrupt). Re-running never re-downloads or rewrites finished work. |
| 2026-10-21 | **Dump rows stay in Parquet** behind DuckDB views (`dump_item_price`, `dump_currency_price`, which add `day_offset`) rather than being copied in. Code the site reads must use real tables, not these views. |
| 2026-10-21 | **Item identity** = poe.ninja's line `Id` (`ninja:<Id>`), stable across leagues. Currencies get `currency:<slug>`. |
| 2026-10-21 | **Currency price** = midpoint of `chaos_ask` and `chaos_bid`, both kept; confidence is the weaker side's. Every row gets `divine_value` from that day's Divine midpoint. |
| 2026-10-21 | **Malformed dump rows are dropped, not fatal.** Unquoted names with line breaks (Necropolis coffins) spill over several lines; only rows that start with the league name and have the right field count are kept, and the drop count is recorded (`*.dropped.json`). Rows with no name (15 Sanctum relics in Ancestor) are skipped too. |
| 2026-10-21 | **For the first 14 days, hourly exchange prices replace daily ones** for everything on the exchange. The hourly price volume-weights the Chaos and Divine markets, with Divine trades converted at that hour's rate. |
| 2026-10-21 | **A league's `launched_at`** is the first hour it trades on the exchange (Mirage: 2026-03-06 20:00 UTC); hourly `day_offset` is fractional days from it. |
| 2026-10-21 | **Exchange names come from RePoE.** An ambiguous name never merges items: each metadata id becomes `Name (MetadataName)`. |
| 2026-10-22 | **Legacy and Tencent twins don't make a name ambiguous.** Classic fragments and breachstones share their name with a legacy RePoE id that has no stack size and never trades, so the exchange's ids were all labelled `Name (CurrencyShaperFragment1)` and so on, and matched neither the pool nor the dumps. The one stackable global id now keeps the plain name (26 names); Tencent-realm copies don't count either. `LOADER_VERSION` 6 rebuilds each league from pages on disk. |
| 2026-10-21 | **Price mappings** (`tracked_item`) have four groups: Currency (mirrors included), High-tier essences (all Deafening, plus Hysteria/Insanity/Horror/Delirium), Scarabs and Divination cards. Rules in `normalize/tracked.py` apply to every source. |
| 2026-10-21 | **Divination cards:** follow only cards NeverSink's filter shows at Semi-Strict (`EB_LOOT_FILTER_STRICTNESS`), tiers t1–t4. Set size and reward come from RePoE (`divination_card`). A fixed currency/card reward gets an hourly turn-in margin. |
| 2026-10-21 | All market data lives in the gitignored `data/` folder (the default `EB_DATA_DIR`), with backup ignore rules for `*.duckdb`, `*.parquet` and partial downloads. |
| 2026-10-22 | **Incremental exchange loads; the database is never wiped to add data.** `exchange_hour_loaded` tracks loaded hours; a load inserts only new hours and deletes only hours leaving the window. The Divine rate is carried forward from rows already stored (ASOF join), and curated tables are updated by difference. Hour-by-hour loading gives exactly the same rows as one full load; on Allflame a one-hour slide removes and re-adds exactly 531 rows. |
| 2026-10-22 | **The running league keeps its launch fortnight.** A live window is the first 14 days *plus* the latest 14 days, loaded together, so a league like Allflame (launched 2026-07-24 22:00 UTC) feeds both the launch views and the Live page. A running league has no daily dump until it ends. |
| 2026-10-22 | **Launch views stay on the launch fortnight** (`day_offset < 14`). A live league whose loaded hours are all later shows a "past the launch window" note instead of a misleading chart. |
| 2026-10-24 | **The Farming page changes no loader.** It reads `cross_market_hour`, which already holds every traded item, so the keep rule stays, there's no `LOADER_VERSION` bump, rebuild or backup re-upload. Past leagues come from `item_day_history`, each finished fortnight reduced to a row per basket item and day (46,679 rows, ~10 MB on Postgres), like the Launch history. The order-book stock fields aren't loaded (finding 7). |
| 2026-10-24 | **The core pool fetches poe.ninja's ten farming lists** (`core_pool.SOURCES['mechanics']`), so the baskets show only current drops: 10 more conditional requests per daily pool check. poe.ninja may be fetched without asking first; GGG's rules stand (the user). |

## Analysis and scoring

| Date | Decision |
|---|---|
| 2026-10-21 | **Analyses favour recent leagues.** The economy changes every league and the exchange (Settlers, 2024-07) was a structural break, so every tool reports per league, newest first, and summaries are recency-weighted: the newest league counts 1 and each *half-life* leagues back halves it (default 2). Leagues before Settlers are context only. |
| 2026-10-21 | **Launch curves are relative:** price ÷ the item's day-1 price in that league, where day 1 is the *median* of its first 24 hourly prices (a few junk early trades would skew a mean). Baselines on fewer than six traded hours are flagged. |
| 2026-10-21 | **Turn-in figures use the median hour** (set cost, reward value, margin, margin %). Thin card markets have junk hours (The Hoarder averaged 570c a set in Mirage against a typical ~1c), and averaging hourly percentages blows up for near-worthless sets. |
| 2026-10-22 | **Card flip score** (`services/divination.score_turn_ins`): margin %, investment (set cost), profitable hours and volume (full sets traded) are ranked among priced cards and combined as a weighted mean (default weights 4 / 2 / 3 / 3, tunable, as is whether cheap or big sets score better). Ranks, so different units combine fairly and one outlier can't dominate. |
| 2026-10-22 | **Cross-market loops** (`services/cross_market.py`). `cross_market_hour` holds every item-hour traded against both Chaos and Divines, with that hour's rate (not carried forward). Loops are priced at the hour's worst price on every leg; an hour pays only if it beats a fee buffer (default 2%); a league where an item didn't trade in both markets counts 0 for its worst-league share. Items under 1c are filtered by default: dust-priced bulk (Rogue's Markers at ~0.001c) shows gaps that reflect how they trade, not profit. |
| 2026-10-22 | **One scoring method** (`services/scoring.rank_score`) for card flips, loops and the Live page: percentile rank per factor, weighted mean, weights tunable on the page. Loop factors: edge when paying, share of paying hours, worst league's share, volume traded in both markets. |
| 2026-10-22 | **Group timing defaults to Chaos.** In Divines almost every group sinks below its day-1 price because the Divine inflates fastest (86 → 266c in Mirage), which reads as "currency loses value". The Divine view stays available, with an explanation. |
| 2026-10-22 | **Launch picks** (`services/launch_picks.py`, `eb launch picks`): what to buy on day 1, days 2–4 and days 5–10, ranked from the newest five leagues with a complete launch fortnight (recency half-life 2 leagues). Growth is median price on days 12–14 over median price in the window, **in Divines**, because Chaos loses about half its value against Divines over the fortnight. Candidates must cost at most 2 div each, trade at least 20 div a day in both the window and the sale, and have traded in at least 3 of the leagues, which drops each league's own currency (Dead Man's Sulphur, the Mirage coins). Score (`rank_score`): typical growth 0.35, worst league 0.25, consistency (weighted share of all leagues it beat Divines; a missing league counts against it) 0.25, liquidity 0.15. Built on the research database and copied to the site by `eb site seed` (three small tables, replaced whole), since the site holds only the live league. |
| 2026-10-23 | **Backtest the site's own tools before calling them advice** (`analysis/backtest.py`, `eb backtest run`, the Backtest page). A trader with 100 Divines acts on Missed opportunities' top 3 picks an hour late (the earliest anyone could), at most 10 Divines a trade and 10% of what traded, in whole items; Launch picks walk-forward, ranked only from earlier leagues. Each priced fair (hour's average, 1% a trade) and harsh (hour's worst traded price). Only what holds up harsh is presented as advice: the Launch picks. Built locally (it needs past leagues' hours) and stored as one JSON row (`backtest_report`), copied to the site by `eb site seed`. |
| 2026-10-23 | **Card turn-ins and loops backtested with limit orders** (`backtest.card_limit_trades`, `loop_limit_trades`; loops sell the item the hour after and always convert Divines at the worst rate): bid at the recap hour's lowest card price only if the set still pays at the reward's lowest price that hour, optionally ask that hour's average for the reward. Fills are bracketed by two models, *touch* (a trade went past the order) and *strict* (the hour's average did), since hourly data has no queue. The page reports both rather than picking one. Order levels were then tuned on a 5 × 5 grid on Mirage and Allflame and checked on the other three leagues: loops bid halfway up the recap hour's range and ask three quarters up (`LIMIT_ORDERS['loops']['limit_mid']`); cards keep the low bid and average ask. The page shows the two strategies in one table. |
| 2026-10-23 | **Volatile flips on the Backtest page, second after the launch picks** (`backtest.flip_results`, from `analysis/flips.py`; finding 5). A bid that doesn't fill is cancelled and costs nothing, and a filled one usually sells within hours, so it may be the best earner if a league launch's busy market fills the bids. The page shows all four fill models side by side rather than picking one, since hourly data can't show whether an hour's extremes are real trades. Built with the rest of the report by `eb backtest run` (it grew from 67 to 72 KB). The Market recap doesn't list flips yet. |
| 2026-10-23 | **Flips are priced and placed in the Chaos market, in whole-number lots** (`missed.whole`, `LOT_MAX` 20, `FLIP_MIN_RANGE` 10%). Exchange orders are whole numbers on both sides and fill in whole lots, and the Divine market's whole-number trades of items worth a few Divines inflated the combined range (finding 5). The recap shows each flip as the orders to place (for example 50c for 3, then 22c each); the backtest fills them lot by lot. Returns barely changed; the recap's candidates went from 30 to 10 on the same hour. |
| 2026-10-23 | **Every recap order in whole numbers, loops and cards too.** `missed.whole` also covers items worth less than a currency unit (up to `UNITS_MAX` 50 units: 5c for 64, 1 Divine for 1,926), and the backtest's loop and card limit orders are placed and filled that way (finding 4: the loops lose most). The Market recap's loop and card popups show the exact orders, computed in the browser with the same rule (`web/src/lib/lots.ts`, tested against the same cases) from the prices the API already sends, so the API is unchanged; a loop also shows its margin at the latest Divine price. |
| 2026-10-24 | **Farming baskets are curated by hand** (`config/mechanics.toml`), reviewed by the user: 20 mechanics, 431 names. Uniques are out (not target-farmed). Breach, Harbinger and Sanctum were dropped: Harbinger is gone and Fracturing Orbs are core drops nobody can target-farm, Breach's currency is glands not listed on trade, Sanctum mostly yields raw currency. Finding 8 rerun without them held. |
| 2026-10-24 | **Mechanics are ranked on three signals** (finding 8): the basket's index against its usual launch path (with past leagues' range, as leagues shift it by about ±60%), the launch outlook (premiums carry over: rank correlation 0.80 / 0.72 / 0.58 for day 1 / days 2–4 / days 5–10) and Easy to sell (stable, 0.86). Being above usual means farm it now, not hold. |
| 2026-10-24 | **A stack is shown as hours of the market's trading, not a price drop** (finding 7): hourly prices bounce more than a stack moves them and volumes are unsigned, so no percentage can be calibrated. Banded at ¼ h and 1 h, the Chaos market first. |
| 2026-10-24 | **Hour of day is a sentence, not a chart** (finding 6): items are dearest in the UTC evening, by ~5% on days 0–2 and under 1% after a week; the lasting effect is the Divine's own cycle (cheapest in Chaos around 12:00 UTC). The page says when timing barely matters. |
| 2026-10-25 | **Price check's verdict: the item's own past-league path, shrunk, in Divines, days 0–13 only** (finding 9): leave-one-league-out over the five exchange leagues it beats "no change" in every phase of the launch fortnight and every held-out league, while group paths, momentum and the dumps' later days don't. A call ("Sell" / "Hold") ships per phase, thickness, horizon and direction only where it hit ≥ 60% pooled and ≥ 55% in every league; otherwise "No clear signal" (thin markets after day 7, everything after day 13). The outcome is measured from the next 6 hours' fills, not the price now, so finding 7's bounce can't pose as a forecast. Pre-Settlers leagues and the dumps aren't used. |
| 2026-10-25 | **Demand is shelved** ([finding 11](findings.md#11-demand-volume-price-and-stock-dont-make-a-buy-label-one-launch-week-lead-to-paper-trade-being-dumped-describes-it-doesnt-save-money), [demand.md](demand.md)). Volume, price and the exchange's stock fields don't make a buy or sell label that beats the item's own recent move, and the one lead is small, concentrated on launch days 1–2 and fading in the newest leagues: too sparse and inconsistent to build or paper-trade. Stock fields stay unloaded. Don't propose Demand again unless new data changes the picture. |
| 2026-10-26 | **The Farming page's leftovers are renamed** for what they are now: the stack seller's constants are `sell_helper_report`, built by `eb sell-helper build` (were `farming_report` and `eb farming build`), and the mechanic baskets are `hours.mechanic_baskets`. The schema renames the table in place (`ALTER TABLE IF EXISTS … RENAME`, before its `CREATE`), so the local copy, a hosted site and the backup keep their report: no rebuild and nothing read from the backup. poe.ninja's "Farming" lists keep their name (it's theirs). |

| Date | Decision |
|---|---|
| 2026-10-21 | **Built as a public site, demoed locally first.** The batch pipeline and read-only serving are separate: CLI jobs write the database, the site only reads, so hosting needs no heavy compute on request. All read logic lives in `services/`, so changing the UI never means rewriting queries. |
| 2026-10-21 | ~~Streamlit is the first, local demo.~~ Superseded 2026-10-22 by the React site. |
| 2026-10-21 | **Units are named everywhere.** KPI cards leave out Chaos (everything is priced in it), and every price column, axis and tooltip names its unit. |
| 2026-10-21 | **Market tables sort by average price over the window** (volume-weighted, in the selected unit). With nothing selected, the chart shows the five most-traded items. |
| 2026-10-22 | **Trading pages put the money first.** The ranked table is full width at the top, columns lead with score and chaos figures (what a card gives comes last), and charts sit at the bottom. |
| 2026-10-22 | ~~**Live market is the landing page**~~ (superseded 2026-10-23 by Missed opportunities), because it's what will be used most. The feed is a separate process (`eb live watch`) and the page only reads. |
| 2026-10-22 | **Widgets whose range depends on the data are hidden when there's only one option** (e.g. "seen in at least N leagues" with one league loaded, as at a launch). Found in Streamlit, which rejects a slider with min = max; the rule stays for the React site. |
| 2026-10-22 | **Charts use linear axes by default**, because players read them. Log scale is an opt-in toggle only where values span orders of magnitude. Relative charts say what the numbers mean (1 = the day-1 price). |
| 2026-10-22 | **The site won't be hosted on Streamlit.** React + Vite + TypeScript on the FastAPI API, Supabase Postgres, a live worker, all on Railway. Unique moves and the other analysis tools aren't in the launch: the focus is investment and trading. |
| 2026-10-22 | **Frontend stack:** React + Vite + TypeScript, TanStack Query and Table (v8), ECharts (lazy-loaded; first load 119 KB gzipped), Tailwind with a small token set, Fira Sans self-hosted. Types are generated from the OpenAPI schema. Dark only; green/red only for profit/loss, gold as the brand. Lines break where hours are missing (a live league's two windows are weeks apart) and isolated hours get a dot. |
| 2026-10-22 | **Streamlit retired.** The React site covers Live market, Arbitrage, Card turn-ins and Launch market. Page tests became API tests (every endpoint after every replayed hour), page budgets became endpoint budgets. The analysis tools stay in `analysis/` for local research. |
| 2026-10-22 | **Live and trading charts show the last 3 days** (`hours`, default 72, up to 28 days for a later "expand"), not the whole window, which left a weeks-long gap in the zoom bar and sent data nobody looked at. The loop chart shows the Chaos price and the price via Divines (at that hour's rate) as lines, so the gap is the margin, with Chaos volume in both markets as bars. |
| 2026-10-22 | **Live market tables:** one "Prices in" switch for both tables, converted in the browser at the league's latest Divine price (from `/api/status`). The loop chart stays in Chaos: converting history at today's rate would misstate it. The look-back control and "Last seen" are gone (scoring keeps 6 hours). Loops show **volume per hour** (Chaos value in both markets in the latest hour) and **items per hour** (units traded in both markets). GGG publishes units, not trade counts. Number boxes can be emptied while typing; empty counts as 0. |
| 2026-10-22 | **Price columns say what kind of price they are**, because the data is hourly, not live. Live loops show **Price (low)** and **Price (high)**, the range traded in the Chaos market in the latest published hour (`price_low`/`price_high`; `price`, the hour's average, still drives the min-price filter). Other columns name their aggregate: *hour avg* (live card turn-ins), *median* (Arbitrage, Card turn-ins: medians of hourly averages), *Day N avg* and *Peak day avg* (Launch: daily volume-weighted averages). |
| 2026-10-22 | **Loop charts keep the Chaos price line through hours without a Divine trade.** The gaps were real: over Allflame's last 3 days the median item traded in both markets in 11 of 72 hours. `cross_market_hour` now also stores Chaos-only hours with the Divine side null (LOADER_VERSION 7; hosted rows 135k → 439k, no perf flags); loops and summaries filter to `BOTH_LEGS`. The via-Divines line and the volume bars are drawn from the both-market hours only, as before. |
| 2026-10-22 | **Launch market page is the launch picks**, replacing the per-item table and multi-line chart: three window tabs (following the live league's current window), a three-bar "your 2 Divines by day 14" comparison (kept as Chaos, a typical item, the #1 pick), cards for the top 3 and a short list for 4–10, each with one dot per reference league. During a window, picks show the live league's latest price against their usual one. The `/api/market/*` endpoints stay for the planned historical section. |
| 2026-10-23 | **Missed opportunities replaces Live market as the landing page** (`services/missed.py`, `/api/missed/{league}`). Without live tracking, the honest pitch is a recap: what the latest published hours offered, framed as what you missed. One response holds the 1, 2 and 3 hour look-backs (≈2.4 KB gzipped, computed once per loaded hour and warmed), so the slider switches locally. Sections: **key movement** (top 3 risers and fallers since the look-back began, with how many hours running they've moved, and the 3 widest high–low ranges; liquid items only, ≥5c and ≥2,000c traded an hour), then the top 3 **loops** and **card turn-ins** by Chaos left on the table (edge × volume in both markets, or margin × sets traded, over paying hours, both loop directions). The headline is the total over every paying loop and turn-in: an upper bound, and labelled as one. No tables: the full lists stay on Arbitrage and Card turn-ins. Prices under a Divine show in Chaos. |
| 2026-10-23 | **League start on the landing page.** The site only learns of a league from GGG's first published page, so the countdown comes from the announcement: `EB_NEXT_LEAGUE` / `EB_NEXT_LEAGUE_START` (UTC), set on the host, reported as `/api/status` `upcoming` until that league has trades. Before launch it's a strip above the running league's recap; from launch it is the page, counting to the estimated first data (end of the first clock hour + 10 min). For the first 6 published hours an "early in the league" note sits on top, and every section has an empty state (the headline says "Nothing paid yet"). Tested by replaying Allflame's real first 3 hours, untrimmed (`tests/fixtures/allflame_start.json.gz`, 57 → 254 → 429 markets): every endpoint answers after each hour. Opportunity cards name the key item instead of a rank number. |
| 2026-10-23 | **Arbitrage and Card turn-ins are card grids with personal filters**, replacing the tables and hourly charts (ECharts is gone from the site). Every option is a card, 24 at a time. Filters run in the browser on the list the page already loaded: **I can invest** (div; presets 1/5/20/100), **min volume / hour** (div traded in both markets, or full sets' value), **min margin**, and sort by best for my capital, margin or volume. "Best for my capital" is a typical hour at the viewer's capital: loops `paying share × min(capital, volume per hour) × edge`; cards `profitable share × min(sets affordable, sets traded per hour) × margin`. Options needing more than the capital for one item or set are counted, not shown. Margins above 300% are hidden by default ("More settings"): they're thin markets' whole-number ratios, and one (Blighted Delirium Orb, +57,535%) otherwise topped the page. The server requests are unchanged, so the cached default views still apply. |
| 2026-10-23 | **Backtest tab, and two tabs lit up in the bar.** Named "Backtest" rather than "Proof of concept", since it shows what doesn't pay as well as what does. Missed opportunities and Backtest are the featured tabs (gold border and tint in the bar), the two pages to start from. |
| 2026-10-23 | **Missed opportunities becomes Market recap.** The backtest found the hourly signals at best break even, so the landing page no longer headlines Chaos "sat on the table". It recaps what traded (counts of loops and turn-ins that paid, the biggest move), offers three options to look into with what the backtest saw for each, and shows each loop's edge and volume instead of a total. Loops need 500c and 10 items through both markets in the hour, and cards a full set traded (`missed.MIN_LOOP_*`, `MIN_CARD_SETS`), since a thin market's single odd trade shows edges over 1,000%; the backtest applies the same floors. Loops and cards are listed steadiest first. API path `/api/missed` unchanged. |
| 2026-10-23 | **Ticker on the Market recap**: the last published hour's 24 biggest liquid movers (`missed.TICKER`, sent with the recap) scroll across the top, about 3 s an item, paused on hover or focus and still for reduced motion. |
| 2026-10-23 | **Arbitrage and Card turn-ins folded into the Market recap.** Their "typical hour with your capital" figure assumed catching every paying hour at the worst prices, which the backtest showed loses when acted on an hour late, and they didn't say what to do now. The recap now lists every loop and card turn-in that paid (top 3, then "Show all"), each with the orders the backtest's best option would place from the latest hour (`missed.LOOP_ORDER`, `CARD_ORDER`; flagged to skip if it wouldn't pay from the bid) and its last 24 hours' price range. No new endpoints: the orders come from columns the recap's queries already read and the ranges from one grouped query, so the recap's reads went from 371 to 375 KB per loaded hour, while dropping the two pages' views saved 64 KB. `/arbitrage` and `/cards` forward to the recap's sections; their endpoints are gone. Per-item history endpoints were considered and rejected: a database read for every item opened, against Supabase's 5 GB of egress a month. |
| 2026-10-23 | **Backtest: "worst case", and the best option per strategy on top.** The market-order rows are named "worst case" (caught at the worst price both hours). The three top cards show the best option tested for each strategy, with the strategy named: launch picks (hold for days), mid-range limit orders for loops and limit orders at the low for cards (trade every hour), each with both fill models and the worst case for comparison. |
| 2026-10-23 | **Market recap: rates on request, ranked by how likely they are to go through.** The orders and 24-hour range sit behind a Show rates button (hover shows them, a click pins them until a click elsewhere or Escape), so the page leads with what to look at, not prices to type in. Each loop and card shows how often the same orders went through in the last 72 hours (`missed.CHANCE_HOURS`): priced from each hour, bought if the next hour traded past the bid, sold if the hour after traded past the ask, the backtest's optimistic fill rule, said so on the page; under 3 tries shows no share. Lists are ordered by whether the order still pays from its bid, then that share. ## Hosting and performance

| Date | Decision |
|---|---|
| 2026-10-21 | ~~**Target hosting: Supabase Postgres for data, Railway for the app and workers.**~~ Superseded 2026-10-23 (everything on Railway). DuckDB stays local. `schema.sql` sticks to SQL both engines run (`DOUBLE PRECISION`, `ON CONFLICT`, `ADD COLUMN IF NOT EXISTS`), and `services/` SQL stays Postgres-compatible (no `GROUP BY ALL` or DuckDB-only functions). The dump loader is exempt: it runs locally on Parquet. |
| 2026-10-22 | **The worker writes Postgres through DuckDB.** `db.site_writer` attaches Postgres to an in-memory DuckDB and the incremental loader runs unchanged; rows and the transaction are Postgres's. Spike on Mirage: 24 new hours in 1.0 s, identical rows, a failed load rolls back. The replay test checks the worker's Postgres tables equal the DuckDB pipeline's. |
| 2026-10-22 | **API results are cached per data version**, not on a timer: computed once per hourly update for all visitors (bounded LRU). On Allflame from Postgres, cached calls take 2–8 ms and the heaviest cold call ~0.3 s. |
| 2026-10-22 | ~~**One image, two Railway services.**~~ Superseded 2026-10-23 (three services, pipeline cron). Web: uvicorn serving `/api` and the built frontend from one origin (no CORS, one service). Worker: `eb live watch`. Locally, a worker container on an empty disk fetched only the 2 new hours (2 requests, 110 KB) and wrote them to Postgres in 2 s. |
| 2026-10-22 | **Tables are served from a cache, never computed per request.** Each is computed once per data version, gzipped once, and sent with an ETag (`304` for a returning client). The data version is trusted for 15 s, so a cached request makes no query. Default tables are precomputed as soon as an hour loads. |
| 2026-10-22 | **Text primary keys stay** (cost issue 8): integer keys would save ~37 MB at hosted scale, not worth a refactor touching everything. Revisit at ~10× the rows. |
| 2026-10-22 | **Performance measurements stay off the site.** The query meter, budgets and `eb perf report` are local and CI tools; live numbers would go in a server-side dev panel later. |
| 2026-10-22 | **ETags include the code version** (a hash of the package's code and SQL, `deps.CODE_VERSION`), not just the data version. Otherwise a deploy that adds a field is answered with 304 and browsers keep the old body until the next hour loads (found when the new loop low/high columns showed blank). Each deploy costs every visitor one full download per view. |
| 2026-10-23 | **The browser asks for new data only when an hour is due.** Before, every visitor polled `/api/status` each minute (60 requests an hour) and refetched on a reload. Now the status is checked when the next hour should be loaded (its end + 8 min, by the server's clock with ours corrected for skew, plus up to 90 s jitter per visitor), then 3, 5 and 10 min apart while it's late (eased from 5/10/20/30 the same day), never under 2 min apart; a stopped feed costs one check per 10 min. The query cache is kept 6 h and saved in localStorage (only the current data version; a new build or 6 h drops it), so page switches and reloads make no request. The server also lets browsers keep a status for 60 s, as a backstop. Each page's settings are remembered per browser and restored from the menu and on a later bare visit. Measured locally: open Arbitrage (status + list), then Card turn-ins (its list only), then Arbitrage again (nothing). |
| 2026-10-23 | **Everything on Railway Hobby: web, Postgres and an hourly pipeline cron** (`deploy/railway/`), replacing Supabase and the always-on worker. *(The pipeline's volume part is superseded the same day: the server is Postgres only, below.)* One bill, a free private network between the services, and the pipeline costs only while it runs (about 2 s an hour). The pipeline (`eb pipeline run`) keeps the research DuckDB and raw pages on its volume (~1.7 GB of the 5 GB limit), so a rebuild re-reads disk and the hosted site gets the Launch picks without a local `eb site seed`; it publishes only new hours to Postgres in one transaction (`site.publish`), and refuses an empty volume instead of backfilling. Chosen after simulating the project locally with Railway's billing (`deploy/railway-sim/`, below). |
| 2026-10-23 | **The Railway project is simulated locally, metered as Railway bills** (`deploy/railway-sim/run.py`): the real image as web, pipeline and Postgres, memory and CPU integrated from `docker stats`, volumes by `du`, egress as the bytes visitors received. The pipeline's only network peer is a stand-in serving pages already on disk with GGG's rules (Allflame replayed from 48 h after launch), so the simulation sends nothing to GGG or poe.ninja. Visitors mirror the built site's caching (`lib/schedule.ts` ported and tested on the same cases). Day: 24 simulated hours at a minute each, idle cost measured separately and scaled to 24 h. Results in [hosting.md](hosting.md#the-railway-bill). |
| 2026-10-23 | **Hashed assets are cached for a year and served pre-gzipped.** The baseline simulation showed assets were 94% of egress (every visit re-downloaded the 224 KB of JS, CSS and fonts: no cache header, and the files sent no 304). `/assets/*` now get `Cache-Control: immutable` for a year (Vite hashes their names), `index.html` `no-cache`; the Dockerfile gzips the build once instead of `GZipMiddleware` compressing the bundle per request. |
| 2026-10-23 | **The server is Postgres only: no DuckDB, no volume, no full history** ([go-live.md](go-live.md)). The pipeline writes Postgres directly (`db.site_writer`). The Launch picks rank from `launch_history`, each finished league reduced to its window medians (~2.5k rows a league): on the real data, identical picks to ranking from 977k hourly rows. The live window's raw pages are kept gzipped in Postgres (`exchange_page`, ~80 MB at most) and pruned as hours leave the window, so a loader rebuild re-reads them instead of downloading again (option 2 of three; dropping them would save about a cent a month). A new server is seeded from the local copy (`eb site seed --hosted`) and then fetches only what's newer, which doubles as the downtime-recovery test; it refuses to run unseeded. |
| 2026-10-23 | **A league switch follows the announcement, never poe.ninja's first-listed league.** The pages on disk show every old league ending 3–4 days before the next launch, with only Standard and event leagues trading in between, so "poe.ninja's current league" is unreliable exactly then. The pipeline keeps the league it follows until the announced one (`EB_NEXT_LEAGUE` / `_START`) has its first published hour, then drops the old one; poe.ninja's list is only a fallback for a database with no league. The core pool comes from the followed league's lists. Items RePoE doesn't know yet (9 in Allflame's first 4 hours) are rechecked daily and the league rebuilt from its stored pages once they're named. Replayed on the real Allflame switch (`tests/test_league_switch.py`). |
| 2026-10-23 | **The hosted API serves only the site's four requests, and an unchanged report isn't re-read.** The pages request `/api/status`, `/api/missed/{league}`, `/api/launch/picks` and `/api/backtest`, all precomputed each hour, so visitors cost no database reads. The endpoints left over from the retired Arbitrage, Cards and Launch-chart pages (`/api/live/*`, `/api/market/*`, `/api/leagues`) took free-form arguments, each new combination computed from the database: on Supabase, egress anyone could run up by scripting them. The Backtest report (67 kB) was re-read every hour though it changes only with `eb backtest run`; its view now has a stamp (its build time), so a new hour reads a few bytes and browsers keep their copy (same ETag): ~48 MB a month less. |
| 2026-10-23 | **The site's database stays on Railway; Supabase's free tier is the off-site backup** ([supabase.md](supabase.md)). Tried as the database the same day, Supabase fitted (~1.4 GB of its 5 GB monthly egress, after the pipeline fix) but every read crossed providers (Railway on Google Cloud, Supabase on AWS) and was billed, so the code grew rules and guardrails around one limit, and a careless full read could use up the month. As a backup it's written every hour (uploads are free) and read only to restore. After each pass the pipeline syncs the site's database to it (`storage/backup.py`): ~25 kB read back, 0.3 s; a failed backup never fails the pass; a league rebuilt by a new loader is emptied and `VACUUM FULL`ed first, so the 500 MB plan isn't doubled (measured: a plain VACUUM let a rebuild grow it 319 → 439 MB). Replaces "no backups" (go-live.md). The local publisher built while Supabase was the database (`local-publisher` branch) isn't needed. |
| 2026-10-24 | **The Farming page is one precomputed document per listed league** (`/api/farming/{league}`, 206 kB, warmed for every league `/api/status` lists, a new one before its first trades included). The hour-of-day and stack constants need numpy, so they're built locally (`eb farming build`, `farming_report`) and seeded, like the backtest report. The pass captures a finished league's Farming history in one transaction; the backup syncs it league by league (~215 B more read a pass). |
| 2026-10-24 | **The API cache drops the old data version's results** when a new one loads: they're never asked for again, but the 256-entry LRU kept ~40 hours of them. With the Farming page that grew the web service from ~190 MB to ~340 MB; dropped, it stays ~190–220 MB (Railway simulation, 60 warmed hours of Allflame). |
| 2026-10-25 | **`item_day_history` is dropped by the schema** (`DROP TABLE IF EXISTS` in `schema.sql`) rather than left unread: the hosted Postgres drops it on the pipeline's next pass, the Supabase backup on its next sync (both run the schema; a DROP reads nothing, so no egress) and the local copy on its next write. That frees ~10 MB of each 500 MB plan at once, and keeps no table that nothing reads or writes. The line is a no-op once the table is gone; remove it after every database has run it. The API serves four requests again. |
| 2026-10-25 | **The fallback page is a Cloudflare Worker that replaces only errors the app didn't send** ([deploy/cloudflare/](../deploy/cloudflare/README.md)). The app stamps `X-EB-Origin: app` on every response (`MarkOrigin` middleware, outermost, so static files, 304s and errors carry it), because it answers 503 (no data yet), 404 and 422 on purpose and the frontend handles them. The Worker swaps in the page for a response of 400+ without the stamp (Railway's edge: a stopped service, a deploy, the usage limit) and for a fetch that throws or takes over 15 s to answer with headers (a healthy cold table takes a few seconds; Cloudflare's own limit is 100 s); the timer stops when headers arrive, so bodies stream. Pages get `503` + HTML, `/api/*` gets **`502`** + JSON, not 503, because `isNoData` shows an API 503 as "No data yet"; both are `no-store` with `Retry-After`. It lives on Cloudflare because the fallback can't depend on Railway, which a hard limit stops. The Worker sends requests to the service's `*.up.railway.app` address (`ORIGIN`), so Railway's certificate for the custom domain doesn't matter. Free plan: 100k requests a day, about 3,000 visitors a day at the simulated 28–35 requests each. |
| 2026-10-25 | **The pipeline pings a dead-man's switch** (healthchecks.io, `EB_HEALTHCHECK_URL`, `ingest/healthcheck.py`): `/start`, then success or `/fail` with the reason. A failure is a pass that raised, a failed backup, or a stopped feed (the followed league's latest hour ended more than 3 h ago, unless the next league is announced and not trading yet: the site's own "ended" rule, now `services/live.upcoming_league`, shared by the API and the pipeline). 3 h, not the banner's 75 min, so one late hour or one failed pass doesn't alarm twice. The switch emails on a `/fail` and on silence, so it also covers a cron that never ran (usage limit, bad deploy), which no in-process check can. It's the user's monitoring service, so it skips `PoliteClient`'s spacing but never fails or slows a pass (5 s timeout, one retry, errors swallowed and the URL kept out of logs). A free uptime monitor on `/api/status` covers the web service (setup only). |
| 2026-10-25 | **Ready for a traffic spike** ([hosting.md](hosting.md#a-traffic-spike-a-streamer-or-a-video)). Cloudflare's edge caches what the origin's Cache-Control allows (the Worker fetches reads with `cacheEverything`); table URLs carry the data version (`?v=`, ignored by the server) so no cache mixes hours; `/api` responses without a header are `no-store`; one computation per cache key; Price check's items in their own 1,024-entry cache as gzipped bytes only; the API keeps its settings instead of rebuilding them per request (cached requests 595 → 4,020 a second on one process).
